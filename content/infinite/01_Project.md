# 項目首頁

> 無限流示例把重點放在「資訊管理」：讀者知道甚麼、角色相信甚麼、真正有效的規則又是甚麼。三者混在一起，很容易寫出自相矛盾的副本。

| 項目 | 示例內容 |
| --- | --- |
| 作品名 | 《第七碼頭》 |
| 類型 | 無限流、規則怪談、懸疑 |
| 一句話簡介 | 四名旅客困在停航多年的第七碼頭，必須從互相矛盾的廣播中找出唯一有效的登船方式。 |
| 本篇目標 | 找到真正船票，四人至少三人離港 |
| 目前進度 | 規則完成；第一輪線索已放入正文 |

## 寫作檢查

- 公開規則必須在違反前出現，讀者才有推理機會。
- 假規則也要有來源，不能只為反轉臨時宣布是假的。
- 每次死亡或失敗都應提供新資訊，避免單純減員。

> 項目首頁適合放整體承諾，不要塞入每張船票的細節。具體證據放進《線索與驗證》，查找時會更快。
